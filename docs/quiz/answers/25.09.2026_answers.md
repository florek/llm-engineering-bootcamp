# Odpowiedzi — 25.09.2026

1. B — Parametry są liczbami uczonymi podczas treningu. Wiedza i wzorce są rozproszone między wieloma parametrami, a nie zapisane według zasady „jeden parametr = jeden fakt”.
2. D — Chinchilla scaling laws podkreślają równowagę między rozmiarem modelu, ilością danych i dostępnymi obliczeniami. Samo dodawanie parametrów nie gwarantuje wykorzystania ich potencjału.
3. A — Training-time scaling zwiększa zasoby używane podczas uczenia, takie jak dane, parametry, GPU i czas treningu. Pozostałe opcje dotyczą pracy gotowego modelu.
4. C — Reasoning daje gotowemu modelowi więcej czasu lub obliczeń podczas tworzenia odpowiedzi. Nie zmienia przy tym liczby wyuczonych parametrów.
5. C — Pobranie aktualnych danych i dodanie ich do kontekstu odpowiada idei RAG, a wieloetapowa analiza jest reasoningiem. Oba mechanizmy działają podczas inferencji.
6. A — Na skali logarytmicznej kolejne wartości 1B, 10B, 100B i 1000B różnią się dziesięciokrotnie. Równe odległości nie oznaczają równych przyrostów liniowych.
7. D — Router kieruje wejście do wybranych ekspertów. Dzięki temu nie wszystkie części modelu muszą pracować przy każdym kroku.
8. B — Total parameters opisują cały model, a active parameters tylko część używaną w danym kroku inferencji. W MoE liczba aktywna może być znacznie mniejsza od całkowitej.
9. A — O możliwościach modelu współdecydują architektura, dane, trening, post-training, tokenizer i sposób użycia. Nowszy mniejszy model może więc przewyższać starszy większy.
10. D — RAG wyszukuje informacje i przekazuje je w kontekście gotowego modelu. Nie musi zmieniać wag ani trenować modelu od nowa.
11. C — LSTM przetwarza sekwencję krok po kroku, więc kolejny krok zależy od poprzedniego. Utrudnia to równoległe obliczenia i skalowanie.
12. B — Prompt engineering skupia się na sformułowaniu polecenia, a context engineering szerzej organizuje wszystkie potrzebne informacje. Kontekst może zawierać dokumenty, dane z API, historię i wyniki narzędzi.
13. A — Każde wywołanie API jest bezstanowe. Iluzja pamięci powstaje dopiero wtedy, gdy aplikacja ponownie przesyła wcześniejsze wiadomości.
14. D — Różne modele mogą używać różnych schematów tokenizacji. `encoding_for_model(...)` dobiera encoding do wskazanego modelu.
15. B — Pusty tekst może oznaczać stronę renderowaną przez JavaScript lub blokadę. Lepiej przerwać albo użyć odpowiedniego renderowania niż pozwolić modelowi zgadywać bez danych.
16. C — `ollama serve` uruchamia serwer, a `ollama pull` pobiera wagi. Przed wywołaniem modelu oba warunki muszą być spełnione.
17. D — Rola `system` przekazuje globalne instrukcje dotyczące tonu, języka, formatu i zachowania modelu. Dane użytkownika trafiają zwykle do roli `user`.
18. A — Pełna historia jest ponownie częścią wejścia przy każdej turze. Im dłuższa rozmowa, tym więcej tokenów wejściowych trzeba przetworzyć i rozliczyć.
19. C — Publiczny ranking nie zastępuje testu na własnym zadaniu. Produkcyjny wybór powinien uwzględniać jakość, koszt i latency na reprezentatywnych danych.
20. B — Autonomia agenta oznacza technicznie wybieranie kolejnego kroku procesu przez model. System wykonuje wskazane narzędzie i zwraca wynik do następnego obiegu pętli.
